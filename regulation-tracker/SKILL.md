# 法规动态追踪

持续追踪世界各国产品认证法规的最新动态，为产品合规提供前瞻性支持。

## 产品范围（由使用者限定）

> ⚠️ 本 skill 不预设任何产品线。**使用时先与使用者确认产品范围**（产品线 + 目标市场 + 关注认证）；使用者未提供时，按全市场通用口径追踪，并在影响分析中注明"未限定产品范围"。

|--------|----------|----------|

## 🌐 全球扫描模式（未限定范围时）

> 使用者未提供产品范围（产品线/市场）时，进入**全球扫描模式**；使用者圈定范围后立即回到精准模式。

**模式切换规则**：

| 使用者输入 | 模式 |
|-----------|------|
| 指定了市场/产品线（如"充电宝+欧盟"） | 精准模式（按指定范围生成 query） |
| 未指定（如"最近有什么法规更新"） | 全球扫描模式（下方批量扫描） |
| 明确说"全都要/全球/所有国家" | 全球扫描模式 |

**全球扫描执行**（广度优先，按「追踪范围」表逐市场批量扫）：

1. 按「追踪范围」表**逐市场生成 query**：`{市场} {主要法规} 修订 2026`（覆盖全部 16 个市场，可拆 2-3 轮执行避免单次搜索过载）
2. 单市场 ≥1 条候选即可纳入摘要；无更新的市场**如实标注"未发现更新"**
3. 输出**全球动态摘要**（非深度影响分析）：按市场分组列出新规发布/生效倒计时/修订，每条带来源URL+日期，未核实的标 ⚠️
4. 摘要生成后**仍走 🔴 CHECKPOINT 确认** → 使用者可从摘要圈定重点市场/产品，转入精准模式深挖
5. 已知局限：全球扫描为广度优先、深度有限；**深度影响分析仍需使用者圈定范围**后执行精准模式

**通过标准**：扫描覆盖 ≥10 个市场（按追踪范围表 16 市场执行）；无更新市场如实标注；摘要每条带来源+生效日期；未核实数据标 ⚠️ 不静默

## 动态分类与关注重点

| 类型 | 触发条件 | 关注重点 |
|------|---------|---------|
| 法规发布 | 新法规/征求意见稿/标准版本更新 | 适用范围、关键要求、生效时间、与现有法规差异 |
| 法规生效 | 生效日期临近(<6个月)/强制执行开始 | 合规差距、测试认证准备、库存处理 |
| 法规修订 | 修订版发布/标准更新/认证规则调整 | 新旧差异、现有证书有效性、补充测试需求 |
| 市场准入 | 新市场要求/互认协议变化/标签更新 | 新增认证要求、标签合规、供应链影响 |

## 追踪流程（每周执行）

| 步骤 | 输入 | 输出 | 通过标准 |
|------|------|------|---------|
| 1. 搜索法规更新 | 本周查询：**精准模式**用使用者范围生成 query（「[市场] [法规] 修订 2026」「EU battery regulation update」）；**全球扫描模式**按「追踪范围」表逐市场批量生成 | 候选清单（来源URL+日期） | ≥3 条候选（无更新时如实报告"未找到更新"）；全球扫描覆盖 ≥10 市场；每条带官方来源URL+日期，≥1 条来自官方公告（官方>行业媒体>标准机构） |
| 2. 对照「产品范围」筛选 | 候选清单 | 相关法规列表 | 先确认使用者限定的产品范围（未提供则进入全球扫描模式）；精准模式逐行核对全部受影响产品线无遗漏；全球扫描模式按市场分组筛选 |
| 3. 用「紧急度矩阵」定级 | 相关法规列表 | 每条优先级标签（🔴/🟠/🟡/⚪） | 每条有且仅有一个标签，并注明定级依据（生效时间+业务影响） |
| 4. 用「解读5步法」分析影响 | 相关法规列表 | 影响分析 | 每条法规 5 步齐全（适用范围/核心要求/时间节点/合规路径/业务影响），业务影响量化到产品线 |
| 5. 生成报告 | 影响分析 | 法规动态追踪报告 | 按「报告模板」：报告日期+覆盖周期+紧急/重点关注分节完整，每条动态含来源+生效日期+行动建议 |
| 6. 更新知识库 | 已确认报告 | memory/ 变更记录（每行一个法规、就地更新、链回周报） | 每条新记录带官方来源URL+更新日期；无来源的标「待核实」，不静默写入 |

**🔴 CHECKPOINT · 🛑 STOP：生成报告前暂停**，将法规清单+影响分析+优先级展示给用户确认（有无遗漏、定级是否合理）。确认后才输出报告并更新知识库。

| | 低业务影响 | 高业务影响 |
|---|---|---|
| **< 3个月生效** | 🟠 中优先 | 🔴 紧急 |

## 新法规解读5步法

1. **适用范围**：什么产品/市场受影响？（对照使用者限定的「产品范围」逐项核对，未限定先询问）
2. **核心要求**：具体限值/测试项/标识要求是什么？
3. **时间节点**：生效日期？过渡期多久？
4. **合规路径**：如何满足？（测试/认证/文档/系统建设）
5. **业务影响**：对现有产品与供应链的具体影响？（量化到产品线）

## 失败模式与兜底

| 触发条件 | 一线处理 | 仍失败兜底 |
|---------|---------|-----------|
| 搜索无结果 | 换关键词+换来源（官方公告>行业媒体>标准机构） | 如实告知"未找到更新"，基于现有知识库回答并标注不确定 |
| 法规不在本表 | 立即 WebSearch 官方来源（EUR-Lex/FCC/CNCA/MIIT） | 无可靠来源→明说"信息待核实"，不编造日期/限值 |
| 市场不在追踪范围表 | 先搜索该国/地区官方监管机构与认证体系（如 query「{国名} {产品线} certification regulator」），确认后按追踪流程抓取 | 仍无法确认官方来源→按全市场通用口径追踪并标"信息待核实"，不编造监管机构/生效日期 |
| 来源信息冲突 | 以官方公告为准，标注差异来源 | 仍分歧→保留双方并注明，交用户判断 |
| 用户数据与我方冲突 | 核对官方来源，确认后更新知识库 | 无法核实→标"待确认"，不覆盖现有记录 |
| 知识库文件缺失 | 用文末模板初始化 memory/ 文件 | 记录本次发现，下次更新时重建 |

## 🔄 自我更新机制（用户反馈驱动）

本 skill 通过使用者反馈持续优化自身，不依赖版本发布：

**① 表外市场被使用者指定 → 自动沉淀并扩表**
- 触发：使用者指定了「追踪范围」表外的市场/法规，且本次运行已核实到官方来源
- 动作：核实记录写入 `memory/regulation-knowledge-base.md`（带来源URL+更新日期）→ 顺手把该市场加入「追踪范围」表（监管机构+主要法规列）→ 更新当日 memory
- 无法核实的部分标 ⚠️ 待核实，**不因使用者指定就默认为真**（仍走官方来源核实）
- 本次已应用：🇨🇱 智利（SEC）、🇳🇬 尼日利亚（SON/NCC）已入知识库与追踪范围表

**② 使用者纠正/反馈 → 核实后更新**
- 触发：使用者指出错误（日期/限值/机构名/范围）、补充新信息、或表达期望的行为
- 动作：先记录反馈到当日 memory → 对照官方来源核实 → 属实则更新 SKILL.md/MEMORY.md/知识库 → 反馈本身（含修正原因）写入当日 memory 备查
- 原则：**反馈不直接等于事实**——以官方来源核实结果为准；无法核实则标待确认并保留双方信息

**③ 每次运行自检**：回答前自查「上次运行后知识库/范围表是否有更新（含使用者新增的市场）」；有更新先加载再回答，避免用过时信息

**通过标准**：使用者指定表外市场后，该市场在当次或下次运行即可从知识库命中（不再现搜）；每次有效反馈都在当日 memory 留有记录（反馈+核实结果）。

## 📧 报告发送（可选）

报告确认后可发送到指定邮箱（手动或每周自动）。

**手动发送**（报告生成并经 🔴 CHECKPOINT 确认后）：
1. 询问收件邮箱（未提供则提示可稍后发送，不阻塞交付）
2. 发送方式二选一：
   - **agent 运行时支持网络**：直接调 Resend API（需环境变量 `RESEND_API_KEY`），`POST https://api.resend.com/emails`（to / subject / html）
   - **配套脚本**：`scripts/send-digest.py --to 邮箱 --report 报告文件.md`（仓库内，见下方说明）
3. 发送失败 → **如实告知错误**（如 401 密钥无效/邮箱非法），报告保留在对话中，不静默丢弃

**自动生成（CI 定时，五种节奏）**：

| 节奏 | 工作流文件 | cron（UTC） | 输出路径 |
|------|-----------|-------------|----------|
| 日报 | `regulation-digest-daily.yml` | `0 1 * * *` | `../reports/<年>/daily/regulation-digest-YYYY-MM-DD.md` |
| 周报 | `regulation-digest.yml` | `0 1 * * 0` | `../reports/<年>/weekly/regulation-digest-YYYY-Www.md` |
| 月报 | `regulation-monthly.yml` | `0 2 1 * *` | `../reports/<年>/monthly/regulation-digest-YYYY-MM.md` |
| 季报 | `regulation-quarterly.yml` | `0 2 1 1,4,7,10 *` | `../reports/<年>/quarterly/regulation-digest-YYYY-Qn.md` |
| 年报 | `regulation-annual.yml` | `0 3 1 1 *` | `../reports/<年>/annual/regulation-digest-YYYY.md` |

日报/周报联网检索最新动态；月报/季报/年报为基于已有周报的**离线聚合**，不联网、不编造。年份由 `date` 动态决定，跨年自动归档到对应目录。

**配置要求**：
- 环境变量 `RESEND_API_KEY`（必填；CI 用 GitHub Secrets，本地用 `.env`）
- 收件邮箱：脚本 `--to` 参数（可多个）或 CI 变量 `DIGEST_TO`

1. **立即更新** `memory/regulation-knowledge-base.md`（法规→状态/日期/要求/来源 + 「来源周报」链接）。**每个法规只保留一行，新动态就地更新该行，不追加重复行；不复制周报叙事，细节留在周报，用「来源周报」列链回。**
2. **记录事件** `memory/YYYY-MM-DD.md`（当日发现+来源URL，agent 自身过程笔记，不与周报重复叙事）
3. **提炼沉淀** → `MEMORY.md` 法规动态跟踪区
- **周报 vs 知识库分工**：`../reports/<year>/weekly/Wxx.md` 是时间线正史（某周发生什么），`memory/regulation-knowledge-base.md` 是当前状态快照（某法规现在怎样）；两者去重规则见 `memory/README.md`。
4. **🔴 更新前自查**：每条数据有官方来源背书、带更新日期；来源不明的不写入

## 绝不做（反例黑名单）

- ❌ **不引用知乎、微信公众号、百度百科**——只认官方公告+权威媒体
- ❌ **不凭记忆回答表外法规细节**——先搜索，搜不到就明说
- ❌ **不静默过期**——知识库记录超3个月未更新标 ⚠️ 提醒复核
- ❌ **不夸大影响**——影响分析严格对照使用者限定的「产品范围」，不扩到未提及的产品线
